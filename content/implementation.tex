\chapter{Implementation}\label{chap:implementation}
Before we go over to the actual pseudocode explaining the different sampling methods are implemented, we first discuss important notes for the framework.
\section{PyTorch}
The framework AL4PDE and therefore our extension is written with usage of PyTorch\footnote{https://pytorch.org/docs/stable/generated/torch.Tensor.backward.html}. Pytorch is an open source machine learning library developed by Meta.
It mainly resolves around the class Tensor, which is a multi-dimensional matrix storing and operating on a single data type. Both the ICs and PDE parameter are stored as such. If an operation is performed using a Tensor, it is stored in an internal graph. PyTorch also provides a method we can apply on a Tensor calles ``backward()''. Here the graph is differentiated using the chain rule, and the gradient is therefore calculated for the current tensor, with regards to the graph leaves. We will utilize this method to calculate the logarithmic gradient of the uncertainty, which we require for the langevin diffusion.
\section{PDE and IC parameters}
Since we are in the context of a Markov chain, we always have the data underlying from the previous state. 
Intuitivly, the data would be the PDE parameter and the IC from the previous state, but in the framework AL4PDE a small change is done.
Instead of directly sampling from the PDE parameters, we sample from a normalized version, with a value between 0 and 1. To transform the normalized parameters to the correct ones, firstly the minimum and maximum value of the PDE are calculated:
\begin{align*}
    cont_{min} &= [\alpha_{min},\beta_{min},\gamma_{min}]+[A_{min}]\cdot5+[\omega_{min}]*5+[0]\cdot5\\
    cont_{max} &= [\alpha_{max},\beta_{max},\gamma_{max}]+[A_{max}]\cdot5+[\omega_{max}]*5+[2\pi]\cdot5
\end{align*}
Each parameter $\alpha,\beta,\gamma$ has the minimal value 0 and the maximum value of 1. The same holds true for the amplitude $A$ and the phase $\omega$. 
Using the values of $cont_{min}$ and $cont_{max}$, the PDE parameter is calculated via:
\[
cont = cont_{norm}\cdot(cont_{max}-cont_{min})+cont_{min}
\]
with $cont_{norm}$ being the normalized parameter. This behaviour is similar for the ICs. 
Firstly, only parameters for the ICs are fetched, and evaluated to the final ICs, with the PDE parameters. The IC parameters are defined through the underlying PDE, e.g. an amplitude or a phase.

Since the maximum value of the amplitude and the phase is 1 and the minimal value is 0, a fetched value outside of the boundary is cropped back to the boundary value.



\section{MALA}
The first step to a working MALA implementation, is defining the proposal kernal described in Eq.~\ref{eq:langevin-diffusion}. 
If we use that knownledge of the parameters for the construction of the Markov chain, instead of directly create a proposal for the ICs and PDE parameters, we rather create a proposal for the IC parameters and the normalized PDE parameters.
This process is demonstrated in Alg. ~\ref{alg:MALA-proposal}. Where $icp$ represents the parameters for an initial condition, and $pdepn$ for the normalized PDE parameters. The $step\_size$ is the learning rate which we can set via a hyperparameter. $I$ is the identity and we take a sample from the normal distribution using $.sample()$.
\begin{algorithm}
    \caption{MALA proposal generation}
    \label{alg:MALA-proposal}
    \begin{algorithmic}[1] 
        \Function{generate\_prop}{$icp, pdepn, step\_size$}
            \Comment{ $step\_size$ learning rate}
            \State $icp\_prop = N(icp + step\_size/2\cdot icp.grad, step\_size\cdot I).sample()$
            \State $pdepn\_prop = N(pdepn + step\_size/2\cdot pdepn.grad, step\_size\cdot I).sample()$
            \State \textbf{return} $icp\_prop, pdepn\_prop$
        \EndFunction
    \end{algorithmic}
\end{algorithm}


To get the values for $icp.grad$ and $pdep.grad$ we have access to the gradient of $icp$ and $pdep$, which was calculated by applying the $.backward()$ from PyTorch function on the uncertainty. Crucially, if a propsal is outside of the definition boundary, it is cropped back to the definition boundary. This could potentially lead to duplicates, however with a small enough step size, this problem can be avoided.
After we generate a proposal (and for the initial Markov state) we calculate the gradient on the logarithmic uncertainty shown in Alg.~\ref{alg:unc-calc}:
  
\begin{algorithm}
    \caption{uncertainty gradient evaluation}
    \label{alg:unc-calc}
    \begin{algorithmic}[1] 
        \Function{uncertainty\_calculation}{$ic, pdep$}
            \State $unc = model\_uncertainty(ic, pdep)$
            \State $log\_unc = log(unc)$
            \State $log\_unc.backward()$
        \EndFunction
    \end{algorithmic}
\end{algorithm}

As soon as a propsal was made, we perform the Metropolis-Hastings step done for MALA. For the calculation we will use the transformation described in Sec.~\ref{sec:MALA}.
If the ratio is higher than a random number between 0 and 1, we accept.
By accepting, we save the proposed values for the IC and PDE parameters in the Markov chain, represented by a list, and use the values
as base for our next iteration. If we reject, the old values are saved in the Markov chain and used
again as base for our next iteration. This comes with the consequence of having samples multiple times
in the Markov chain. The metropolis can be seen in Alg.~\ref{alg:metropolis}
With $unc\_old(IC, \lambda)$ we denote the uncertainty created with the IC and the PDE parameters $\lambda$. 
\begin{algorithm}
    \caption{Metropolis-Hastings step}
    \label{alg:metropolis}
    \begin{algorithmic}[1] 
        \Function{accept\_or\_reject}{$unc\_old(IC_0, \lambda_0), unc\_prop(IC_1, \lambda_1), complete\_list$}
            \State $\alpha = unc\_old(IC_0, \lambda_0)/unc\_prop(IC_1, \lambda_1) * q(X_t|X_{t+1})/q(X_{t+1}|X_{t+1}) $
            \If{$random()<=\alpha$}\Comment{$accept$}
            \State $complete\_list.append(IC\_params_1, IC_1, \lambda\_norm_1, \lambda_1)$
            \State \textbf{return }$IC_1, IC\_params_1, \lambda_1, \lambda\_norm_1, unc\_prop$
            \Else \Comment{$reject$}
            \State $complete\_list.append(IC\_params_0, IC_0, \lambda\_norm_0, \lambda_0)$
            \State \textbf{return }$IC_0, IC\_params_0, \lambda_0, \lambda\_norm_0, unc\_old$
            \EndIf
        \EndFunction
    \end{algorithmic}
\end{algorithm}
If we put everything together, the whole code is in Alg. ~\ref{alg:MALA}. To start the Markov chain, the first values are drawn at random, from samples that have not been trained on.
 
\begin{algorithm}
    \caption{Pseurdocode for MALA}
    \label{alg:MALA}
    \begin{algorithmic}[1] 
        \Function{MALA}{$chain\_size, step\_size$}
            \State $complete\_list = []$
            \State $ic, icp, p, pn = initialize\_first\_values()$
            \State $unc\_cur = uncertainty\_calculation(ic, p)$
            \For{$i$ in range($chain\_size$)}
            \State $icp\_prop, pdepn\_prop = generate\_proposal(icp, pn, step\_size)$
            \State $pdep\_prop = get\_pde\_params(pdepn\_prop)$
            \State $ic\_prop = get\_ic(icp\_prop, pdep\_prop)$
            \State $unc\_prop = evaluate\_uncertaint(ic\_prop, pdep\_prop)$
            \State $ic, icp, p, pn, unc\_cur = accept\_or\_reject(unc\_cur, unc\_prop, complete\_list)$
            \EndFor
        \State \textbf{return } $complete\_list$
        \EndFunction
    \end{algorithmic}
\end{algorithm}

At the end we have a Markov chain containing $chain\_size$ samples. We then used the whole chain as input for our numerical solver to generate a solution and thereby 
used as training set for our neural PDE solver. 

\section{SC-ULA}
For the implementation of SC-ULA, instead of the Metropolis-Hastings step, it rather just updates all parameters accordingly. The created chain then is further processed by the numerical solver.
\begin{algorithm}
    \caption{Pseudocode for SC-ULA}
    \label{alg:SC-ULA}
    \begin{algorithmic}[1] 
        \Function{SC-ULA}{$chain\_size, step\_size$}
            \State $complete\_list = []$
            \State $ic, icp, p, pn = initialize\_first\_values()$
            \State $unc\_cur = uncertainty\_calculation(ic, p)$
            \For{$i$ in range($chain\_size$)}
            \State $complete\_list.append(ic, icp, p, pn)$
            \State $icp\_prop, pdepn\_prop = generate\_proposal(icp, pn, step\_size)$
            \State $pdep\_prop = get\_pde\_params(pdepn\_prop)$
            \State $ic\_prop = get\_ic(icp\_prop, pdep\_prop)$
            \State $unc\_prop = evaluate\_uncertainty(ic\_prop, pdep\_prop)$
            \State $ic, icp, p, pn, unc\_cur = ic\_prop, icp\_prop, pdep\_prop,  pdepn\_prop, unc\_prop$
            \EndFor
        \State \textbf{return } $complete\_list$
        \EndFunction
    \end{algorithmic}
\end{algorithm}

\section{PC-ULA}
To modify SC-ULA for use in PC-ULA, we can use SC-ULA as a base. Instead of initializing a single tuple of values, we create $n$ tuples in parallel. Since we're using PyTorch, parallel computation is supported by default, so the core code remains largely unchanged-only the dimensionality of the tensors increases.

The algorithm begins by sampling the first $n$ values, which serve as the starting points for the chains. It then calculates the uncertainty for each of these $n$ values and generates the corresponding proposal states in parallel. At the end of the process, the algorithm discards the first $n - 1$ states, retaining only the final one.

\begin{algorithm}
    \caption{Pseudocode for PC-ULA}
    \label{alg:PC-ULA}
    \begin{algorithmic}[1] 
        \Function{SC-ULA}{$chain\_size, step\_size, n$}
            \State $complete\_list = []$
            \State $ic, icp, p, pn = initialize\_n\_first\_values(n)$
            \State $unc\_cur = uncertainty\_calculation(ic, p)$
            \For{$i$ in range($chain\_size$)}
            \State $complete\_list.append(ic, icp, p, pn)$
            \State $icp\_prop, pdepn\_prop = generate\_proposal(icp, pn, step\_size)$
            \State $pdep\_prop = get\_pde\_params(pdepn\_prop)$
            \State $ic\_prop = get\_ic(icp\_prop, pdep\_prop)$
            \State $unc\_prop = evaluate\_uncertainty(ic\_prop, pdep\_prop)$
            \State $ic, icp, p, pn, unc\_cur = ic\_prop, icp\_prop, pdep\_prop,  pdepn\_prop, unc\_prop$
            \EndFor
        \State $complete\_list = complete\_list(-n:)$\Comment Take the last $n$-values
        \State \textbf{return } $complete\_list$
        \EndFunction
    \end{algorithmic}
\end{algorithm}
