\chapter{Implementation}\label{chap:implementation}
The first step to a working MALA implementation, is defining the proposal kernal described in Eq.~\ref{eq:langevin-diffusion}. 
Since we are in the context of a Markov chain, we always have the data underlying from the previous state. 
Intuitivly, the data would be the PDE parameter and the IC from the previous state, but in the framework AL4PDE a small change is done. Firstly, a normalized PDE Parameter is fetched which then gets further calculated to the corrct PDE parameters. This is similar for the ICs: Firstly, only parameters for the ICs are fetched, and evaluated to the final ICs, with the PDE parameters. The IC parameters are defined through the underlying PDE, e.g. an amplitude or a phase. 

If we use that knownledge for the construction of the Markov chain, instead of directly create a proposal for the ICs and PDE parameters, we rather create a proposal for the IC parameters and the normalized PDE parameters.
This process is demonstrated in Alg. ~\ref{alg:MALA-proposal}. Where $icp$ represents the parameters for an initial condition, and $pdepn$ for the normalized PDE parameters. The $step\_size$ is the learning rate which we can set via a hyperparameter. $I$ is the identity and we take a sample from the normal distribution using $.sample()$
\begin{algorithm}
    \caption{MALA proposal generation}
    \label{alg:MALA-proposal}
    \begin{algorithmic}[1] 
        \Function{generate\_prop}{$icp, pdepn, step\_size$}
            \Comment{ $step\_size$ learning rate}
            \State $icp\_prop = N(icp + step\_size/2\cdot icp.grad, step\_size\cdot I).sample()$
            \State $pdepn\_prop = N(pdepn + step\_size/2\cdot pdepn.grad, step\_size\cdot I).sample()$
            \State \textbf{return} $icp\_prop, pdepn\_prop$
        \EndFunction
    \end{algorithmic}
\end{algorithm}


To get the values for $icp.grad$ and $pdep.grad$ we have access to the gradient of $icp$ and $pdep$, which was calculated by applying the $.backward()$ function on the uncertainty. Crucially, if a propsal is outside of the definition boundary, it is cropped back to the definition boundary. This could potentially lead to doublicates, however with a small enough step size, this problem can be avoided.
After we generate a proposal (and for the initial Markov state) we calculate the gradient on the logarithmic uncertainty shown in Alg.~\ref{alg:unc-calc}:
  
\begin{algorithm}
    \caption{uncertainty calculation}
    \label{alg:unc-calc}
    \begin{algorithmic}[1] 
        \Function{uncertainty\_calculation}{$ic, pdep$}
            \State $unc = model\_uncertainty(ic, pdep)$
            \State $log\_unc = log(unc)$
            \State $log\_unc.backward()$
            \State \textbf{retrun} $unc$
        \EndFunction
    \end{algorithmic}
\end{algorithm}

As soon as a propsal was made, we perform the Metropolis-Hastings step done for MALA. For the calculation we will use the transformation described in Sec.~\ref{sec:MALA}.
If the ratio is higher than a random number between 0 and 1, we accept.
By accepting, we save the proposed values for the IC and PDE parameters in the Markov chain, represented by a list, and use the values
as base for our next iteration. If we reject, the old values are saved in the Markov chain and used
again as base for our next iteration. This comes with the consequence of having samples multiple times
in the Markov chain. The metropolis can be seen in Alg.~\ref{alg:metropolis}
With $unc\_old(IC, \lambda)$ we denote the uncertainty created with the IC and the PDE parameters $\lambda$. 
\begin{algorithm}
    \caption{Metropolis step }
    \label{alg:metropolis}
    \begin{algorithmic}[1] 
        \Function{accept\_or\_reject}{$unc\_old(IC_0, \lambda_0), unc\_prop(IC_1, \lambda_1), complete\_list$}
            \State $\alpha = unc\_old(IC_0, \lambda_0)/unc\_prop(IC_1, \lambda_1) * q(X_t|X_{t+1})/q(X_{t+1}|X_{t+1}) $
            \If{$random()<=\alpha$}\Comment{$accept$}
            \State $complete\_list.append(IC\_params_1, IC_1, \lambda\_norm_1, \lambda_1)$
            \State \textbf{return }$IC_1, IC\_params_1, \lambda_1, \lambda\_norm_1, unc\_prop$
            \Else \Comment{$reject$}
            \State $complete\_list.append(IC\_params_0, IC_0, \lambda\_norm_0, \lambda_0)$
            \State \textbf{return }$IC_0, IC\_params_0, \lambda_0, \lambda\_norm_0, unc\_old$
            \EndIf
        \EndFunction
    \end{algorithmic}
\end{algorithm}
If we put everything together, the whole code is in Alg. ~\ref{alg:MALA}. To start the Markov chain, the first values are drawn at random, from samples that have not been trained on.
 
\begin{algorithm}
    \caption{MALA}
    \label{alg:MALA}
    \begin{algorithmic}[1] 
        \Function{MALA}{$chain\_size, step\_size$}
            \State $complete\_list = []$
            \State $ic, icp, p, pn = initialize\_first\_values()$
            \State $unc\_cur = uncertainty\_calculation(ic, p)$
            \For{$i$ in range($chain\_size$)}
            \State $icp\_prop, pdepn\_prop = generate\_proposal(icp, pn, step\_size)$
            \State $pdep\_prop = get\_pde\_params(pdepn\_prop)$
            \State $ic\_prop = get\_ic(icp\_prop, pdep\_prop)$
            \State $unc\_prop = uncertainty\_clarification(ic\_prop, pdep\_prop)$
            \State $ic, icp, p, pn, unc\_cur = accept\_or\_reject(unc\_cur, unc\_prop, complete\_list)$
            \EndFor
        \State \textbf{return } $complete\_list$
        \EndFunction
    \end{algorithmic}
\end{algorithm}

At the end we have a Markov chain containing $chain\_size$ samples. We then used the whole chain as input for our numerical solver to generate a solution and thereby 
used as training set for our neural PDE solver.
